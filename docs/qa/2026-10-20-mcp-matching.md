## 연결된 워크스페이스

커넥터 하나는 워크스페이스 하나에만 연결됩니다. 켤 때 확인해서 설정 Tools 탭과 빚기 카드에 보여 줍니다.

| 서비스 | 확인 도구 | 이 맥에서 연결된 곳 |
|---|---|---|
| Notion | `notion-get-self` | Wozz |
| Linear | `get_workspace` | Project3 |
| Figma | `whoami` | spigel's team |

다른 워크스페이스를 읽으려면 claude.ai 설정에서 커넥터를 다시 연결해야 합니다. 앱이 워크스페이스를 고를 수는 없습니다.

## 서비스별로 무엇을 어떻게 찾나

| 서비스 | 앱이 정하는 것 | Claude가 정하는 것 | 검색 방식 |
|---|---|---|---|
| Notion | 보낼 낱말(C1에서 켠 칩) | 검색어, 몇 번 찾을지, 어느 페이지를 고를지 | **키워드 검색.** 자연어 AI 검색은 Notion AI가 있는 Business·Enterprise 플랜에서만 되고, 이 워크스페이스는 키워드 검색 |
| Linear | 보낼 낱말 | 검색어, 고를 이슈 | `list_issues`의 query = 이슈 제목·설명 글자 검색 |
| Figma frame | **어느 프레임을 읽을지**: 할 일에 연결된 바로가기, 없으면 제목·낱말에 이름이나 부르는 말이 들어간 바로가기 | 프레임 안 글 중 낱말과 관련된 것을 고르고 요약 | 프레임 레이어(`get_metadata`), 글이 부족하면 디자인 내용(`get_design_context`) |

## 고치기 전에 보인 문제

| 문제 | 근거 |
|---|---|
| 검색 도구를 한 번도 안 부르고 “없음”을 냄 | Notion “포트폴리오” 4.2초, Linear “디자인, QA” 3.8초. 부른 도구 0개 |
| 낱말을 문장처럼 붙여 검색 | Notion `"면접 준비"` 한 번. 키워드 검색이라 덜 맞음 |
| 허용하지 않은 피그마 도구를 시도 | `get_design_context`, `get_screenshot`을 매번 시도(허용 목록 밖이라 막힘) |
| 어느 워크스페이스를 읽는지 알 수 없음 | 앱 어디에도 표시 없음 |

## 고친 것

1. **CLAUDE.md collect 규칙**
   - 답하기 전에 검색 도구를 꼭 부른다.
   - Notion·Linear는 낱말을 문장으로 붙이지 말고 가장 특이한 낱말 하나로 검색하고, 없으면 다른 낱말로 최대 3번까지 다시 찾는다.
   - 피그마는 낱말과 관련된 글이 있을 때만 결과를 낸다.
2. **앱이 검사**: 검색 도구(`notion-search`, `list_issues`, `get_metadata`·`get_design_context`)를 한 번도 안 불렀으면 한 번 더 시키고, 그래도 안 부르면 “없음”이 아니라 “읽지 못함”으로 표시한다(`searched()`).
3. **피그마**: `get_design_context`를 허용(읽기 전용). `get_screenshot`은 계속 막는다.
4. **워크스페이스**: 켤 때 읽기 테스트 대신 whoami 도구로 워크스페이스·계정을 확인해 저장하고, Tools 탭(`Works · reads "Wozz"`)과 빚기 카드(`MCP · WOZZ`)에 보여 준다.

## 남은 것

- **관련성은 Claude 판단입니다.** Linear “디자인, QA”로 고른 이슈의 제목에는 두 낱말이 모두 없습니다. 설명에 있을 수 있어서 앱이 걸러 내지는 않았습니다. 이상하면 C1에서 그 도구를 끄면 됩니다.
- **Claude가 낱말을 넓혀 검색하기도 합니다.** “운동, 루틴”에 `헬스`로도 찾았습니다. 규칙은 다른 낱말로 바꾸라고만 해서 막지 않았습니다.
- **피그마는 바로가기 프레임만 읽습니다.** 할 일에 맞는 바로가기가 없으면 Figma frame 카드는 “Nothing matched”입니다. 파일 안 다른 프레임을 찾아 들어가지는 않습니다.
- Gmail은 여전히 Claude Code 안에서 다시 인증해야 합니다.
