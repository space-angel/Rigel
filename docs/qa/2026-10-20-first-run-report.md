## 어떻게 테스트했나

- `src/main/e2e.ts` 시나리오 실행기로 창을 화면에 띄우지 않은 채 클릭과 입력을 흉내 내고, 단계마다 스크린샷을 남겼습니다. 사용 중인 화면과 다른 앱(피그마, 터미널, 브라우저)은 열지 않습니다.
- 데이터는 매번 빈 폴더에서 시작했습니다. 첫 실행 시나리오는 이 맥의 실제 Claude Code(2.1.304, sonnet)와 claude.ai Notion·Figma 커넥터를 썼습니다.
- 실제로 만들기 어려운 상황 두 가지는 따로 돌렸습니다.
  - Claude Code 없음: claude 경로를 틀리게 넣은 데이터로 시작
  - MCP 인증 필요: `docs/qa/fixtures/fake-claude-mcp-auth.sh`가 Notion을 `needs-auth`, Linear 읽기를 실패로 돌려줌

다시 돌리는 방법:

```
npm run build
TODOBAN_USER_DATA=<빈 폴더> TODOBAN_E2E=docs/qa/first-run.e2e.json TODOBAN_E2E_OUT=<결과 폴더> npx electron .
```

## MCP 연결 확인 흐름 (새로 만듦)

| 단계 | 동작 | 3회차 측정 |
|---|---|---|
| 1. 상태 읽기 | claude를 띄워 시작 메시지(init)의 서버 상태만 읽고 바로 끔. 모델을 부르지 않음. 아직 연결 중인 서버만 `claude mcp list`로 다시 봄. 5분 동안 기억 | 시작하기 창에서 3~5초, 이후 Tools 탭은 0.4초 |
| 2. 상태 표시 | Connected / Connecting / Needs sign-in / Not added | |
| 3. 켤 때 읽기 테스트 | 켜는 순간 실제로 한 번 읽음. 되면 “Works · read in 15.3s”, 안 되면 다시 끄고 이유를 보여 줌 | Notion 15~20초, Figma frame 14~17초 |
| 4. 안내 | Needs sign-in → 터미널 열기, `claude`, `/mcp`, 브라우저에서 로그인. Not added → Claude → Settings → Connectors 열기 | |
| 5. 다시 확인 | 터미널이나 브라우저에서 돌아와 설정 창에 포커스가 오면 자동으로 다시 확인 (10초 안에는 생략) | |
| 6. 빚기 화면 | 인증이 필요한 MCP 카드는 “Needs sign-in · open Settings”, 누르면 Tools 탭으로 | |

## 아직 확인하지 못한 것

- 캘린더: 처음 켜면 macOS 권한 창이 떠서 자동 테스트로 돌리지 않았습니다.
- Gmail: 이 맥에서는 Claude Code 안에서 다시 인증해야 합니다. 앱이 Needs sign-in으로 보여 주는 것까지만 가짜 claude로 확인했습니다.
- Linear: 실제로 켜서 읽기 테스트를 하지 않았습니다. 실패 처리만 가짜 claude로 확인했습니다.
- 실제 마우스와 키보드: 메뉴바 아이콘 클릭, ⌥ Space, 끌어서 순서 바꾸기, 키보드 이동은 자동 테스트에 없습니다. 클릭은 화면에 띄우지 않은 창 안에서 흉내 낸 것입니다.
- 어제 할 일 가져오기, Phantom 테마.

- 확인 창에서 4개를 넣었는데 목록에는 1개만 보일 수 있습니다. 내일 날짜(10/21)와 나중 할 일은 Later 묶음에 들어가기 때문입니다. “Later 3”이 보이긴 하지만, 넣은 직후 어디로 갔는지 알려 주는 게 좋겠습니다.
- 확인 창이 결과를 받는 순간 아주 잠깐 “0 tasks from your thought”가 보일 수 있습니다. 결과를 복사하는 effect가 한 번 늦게 돌기 때문입니다.
